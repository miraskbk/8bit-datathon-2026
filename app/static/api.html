Инструкция для жюри

API проверки видео

Тот же сервис и результаты, что в интерфейсе. Два запроса с заголовком X-API-Key. Все модели работают локально внутри сервиса.

1. Адрес и ключ

Используйте публичный HTTPS-адрес, полученный от команды. Для локального запуска адрес — http://127.0.0.1:8003. Команда передаёт API-ключ отдельно. Ключ отсутствует в GitHub, URL и открытых страницах. В командах ниже замените адрес и ключ своими значениями.

export SERVICE_URL='https://your-team-domain.example'
read -r -s JURY_API_KEY
export JURY_API_KEY

2. Готовность

GET /health возвращает состояние моделей. GET /ready возвращает HTTP 200 только после загрузки моделей, иначе 503. Уточните ограничения через GET /api/v1/capabilities.

3. Загрузка MOV

curl --fail-with-body -X POST "$SERVICE_URL/api/v1/analyze" \
  -H "X-API-Key: $JURY_API_KEY" \
  -F 'file=@your-video.mov'

Ответ HTTP 202:

{"job_id":"3f2a9c1e3f2a9c1e3f2a9c1e3f2a9c1e","status":"processing"}

4. Опрос результата

curl --fail-with-body \
  "$SERVICE_URL/api/v1/jobs/3f2a9c1e3f2a9c1e3f2a9c1e3f2a9c1e" \
  -H "X-API-Key: $JURY_API_KEY"

Повторяйте запрос примерно раз в 2 секунды до done или failed. На обработку жюри отводит 5 минут. При стандартной конфигурации сервер завершает или останавливает задачу за 270 секунд после начала приёма файла обработчиком. Проверяйте сервис на целевом оборудовании до сдачи.

{
  "job_id": "3f2a9c1e3f2a9c1e3f2a9c1e3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Название наблюдаемого события",
    "timecode_sec": 44.2,
    "description": "Видимое действие и основание для проверки человеком",
    "evidence_frames": [{
      "timestamp_sec": 44.2,
      "image_base64": "<JPEG, закодированный в base64>"
    }],
    "rule": {
      "document": "Название акта РК",
      "section": "Пункт или раздел",
      "url": "https://adilet.zan.kz/rus/docs/..."
    }
  }]
}

Это пример схемы, а не результат реального видео. Каждый готовый положительный результат содержит 1–3 настоящих JPEG-кадра на событие. no_violation сопровождается пустым списком violations. Для processing и failed вердикт равен null. Поля rule, metadata, confidence и error расширяют обязательную схему.

Ограничения и ошибки

КодЗначение
401Отсутствует или неверен X-API-Key
404Проверка не найдена или срок хранения истёк
413Превышен размер файла или запроса
415Неверное расширение. Допускается .mov и .MOV
422Пустой, повреждённый, неподдерживаемый или слишком длинный файл, превышение разрешения
429Все места заняты. Retry-After: 15. По умолчанию одна задача за раз
503Модели не готовы на /ready

Стандартные ограничения: 35 МиБ, 180 секунд, до 3840 × 2160 пикселей на кадр, одна принятая задача. Записывайте job_id для диагностики. Если связь пропала после получения номера, продолжайте опрашивать эту задачу вместо повторной загрузки.

Данные и трактовка результата

Сервис отклоняет запросы к защищённым путям без ключа до разбора загружаемого файла. Видео удаляется после обработки или восстановления после перезапуска. Результаты и кадры доступны с ключом в течение часа, затем удаляются. Промежуточные данные удаляются после задачи, аварийные остатки — по сроку хранения. Выгруженные вами отчёты остаются на вашем устройстве.

Звук и идентификация лиц не используются. Сервис не обучается на загруженных файлах и не отправляет видео, кадры или их описания облачным AI-сервисам. Невидимые операции, полномочия людей и завершение транзакций не подтверждаются по видео. Результат требует проверки человеком.
