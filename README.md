# Forte Vision Review

Рабочий прототип для кейса ForteBank: локально анализирует `.mov`-записи кассовой
зоны, возвращает `violation` / `no_violation`, локализует возможные нарушения и
показывает проверяющему кадры-доказательства и источник правила.

Исходные видеозаписи, таблица организатора и файл кейса намеренно не публикуются в
репозитории. Поместите их локально в `open/videos`, `open/open_labels.xlsx` и корень
проекта соответственно, если требуется повторное обучение.

## Что готово

- Temporal R3D-18 анализирует 4-секундные последовательности по всей записи.
- Небольшая бинарная голова обучена на предоставленных 42 размеченных роликах.
- Тип события определяется отдельным поиском по 66 вручную проверенным визуальным
  прототипам семи категорий; таймкод и имя файла не являются входами классификатора.
- Для каждого срабатывания возвращаются тип, точный таймкод, описание, confidence,
  три JPEG в base64 и ссылка на открытый нормативный источник.
- Несколько соседних положительных окон объединяются в одно событие; раздельные
  эпизоды возвращаются отдельными элементами.
- Загрузка и получение результата асинхронны и защищены `X-API-Key`.
- Веб-интерфейс находится на `/`, OpenAPI — на `/docs`, health check — на `/health`.
- Инференс выполняется локально: видео не отправляется во внешние API, аудио и
  распознавание лиц не используются; временный файл удаляется после анализа.

## Запуск

```bash
uv sync --extra dev
cp .env.example .env
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Откройте <http://localhost:8000>. Демонстрационный ключ: `jury-demo-key`.
Для публичной демонстрации разверните тот же Docker-образ на хосте с публичным HTTPS
URL и задайте секретный `API_KEY`; внешние AI-сервисы при этом не нужны.

### Docker

```bash
docker build -t forte-vision-review .
docker run --rm -p 8000:8000 -e API_KEY=replace-me forte-vision-review
```

Во время сборки Docker скачивает веса R3D-18. После сборки контейнер запускается
с `HF_HUB_OFFLINE=1` и способен выполнять анализ без доступа к интернету.

## API жюри

### 1. Поставить MOV в очередь

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H 'X-API-Key: jury-demo-key' \
  -F 'file=@open/videos/X-1.mov'
```

Ответ `202 Accepted`:

```json
{"job_id":"34f5adfd1050","status":"processing"}
```

### 2. Получить статус или результат

```bash
curl http://localhost:8000/api/v1/jobs/34f5adfd1050 \
  -H 'X-API-Key: jury-demo-key'
```

Во время обработки `status` равен `processing`. Финальный ответ имеет `status: done`,
`verdict: violation|no_violation` и массив `violations`. Ошибка обработки возвращается
как `status: failed` и поле `error`.

Пример сокращенного результата:

```json
{
  "job_id": "34f5adfd1050",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Ценности оставлены без контроля",
    "timecode_sec": 22.0,
    "description": "...",
    "evidence_frames": [
      {"timestamp_sec": 21.5, "image_base64": "/9j/4AAQ..."}
    ],
    "rule": {"document": "...", "section": "...", "url": "https://..."},
    "confidence": 0.91
  }]
}
```

## Переобучение

Исходная разметка читается прямо из `open/open_labels.xlsx`, включая русские значения
`нарушение` / `нет нарушения` и таймкоды вида `1 мин 8 сек`.

```bash
uv run violation-train \
  --labels open/open_labels.xlsx \
  --videos open/videos \
  --output artifacts/forte_r3d_head.pt
```

Первый запуск извлекает R3D-признаки и сохраняет локальный кэш
`artifacts/train_features.npz`. Для повторного обучения головы:

```bash
uv run violation-train --reuse-features
```

Категории и видимые признаки находятся в `open/violation_types.csv`. После их правки
визуальные прототипы перестраиваются отдельной командой:

```bash
uv run violation-train-types
```

## Архитектура и ограничения

R3D-18 с весами Kinetics-400 кодирует движение в 16 кадрах; обученная линейная голова
оценивает вероятность нарушения. Для положительного события тот же temporal embedding
сопоставляется с вручную проверенными примерами разных действий: передача наличных,
открыто оставленные ценности, доступ второго человека, незаблокированное рабочее место,
личные вещи и еда/напитки. Это не распознавание личности и не юридическое заключение.

Набор мал и содержит только бинарную разметку, без истинного типа нарушения. Поэтому
файл `violation_types.csv` является документированной экспертной разметкой видимых
действий, а классификация типа — гипотезой для проверки человеком. Для честной
оценки на новых камерах нужно дополнить разметку типами событий и отложенной выборкой,
разделенной по ракурсу/локации, затем откалибровать `DECISION_THRESHOLD`.

В исходном наборе `Х-4.mov` и `Х-47.mov` являются побайтово одинаковыми файлами, но
имеют разные контрольные таймкоды — 57 и 68 секунд. Модель считает их двумя отдельными
эпизодами; API поддерживает несколько элементов в `violations`, поэтому не скрывает это
противоречие разметки.

## Проверки

```bash
HF_HUB_OFFLINE=1 uv run pytest -q
```

Перед показом рекомендуется прогнать `X-1.mov` (ожидаемый эпизод около 22 секунды),
несколько отрицательных роликов и видео с отличающегося ракурса.
